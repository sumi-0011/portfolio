# eXemble
온프레미스로 여러 고객사에 설치하는 AI 통합 플랫폼. 사용자는 기능 단위인 노드를 캔버스에 이어 붙여 AI 업무 흐름(워크플로우)을 만들고, 채팅으로 바로 실행합니다. 워크플로우와 AI 채팅의 FE 설계/개발을 담당하고, 2026년 1분기부터 FE 파트(3명)를 리딩하고 있습니다. 2025.12 v1.0 출시.

**스택** `React 19` `TypeScript` `React Flow` `Zustand` `Zod` `TanStack Query` `SSE` `Vitest`

## [워크플로우] 노드 확장 구조 설계
2025.09 ~ 현재

고객사 요구에 따라 노드 종류가 계속 늘었습니다. 그런데 노드 하나를 추가하거나 수정하려면 여러 공통 파일을 함께 고쳐야 했고, 한 곳을 빠뜨려도 빌드 에러가 나지 않았습니다.

- 요구가 들어오면 FDE(고객사 현장 엔지니어)와 배경부터 확인하고, **새 노드를 만들지 기존 노드의 기능으로 넣을지** 판단해 노드 종류가 불필요하게 늘지 않게 관리했습니다.
- 흩어져 있던 노드의 설정·검증·변환을 노드 폴더 하나에 모아, **해당 폴더만 수정하면 되는 Registry 구조**로 설계했습니다.
- 노드 등록을 빠뜨리면 **컴파일 단계에서 에러가 나는 타입 구조**를 만들고, 누가 추가하든 같은 절차를 따르는 노드 추가용 Agent Skill을 만들었습니다.

#### 결과

- 지원 노드 종류 **2배 이상**, 2026년 1분기 워크플로우 기능 개선 **20건 이상** 출시
- 팀원들도 같은 방식으로 새 노드(이메일·차트 등)를 추가

## [편집기 사용성] 워크플로우 편집기 사용성 개선
2026.01 ~ 현재

- 참고 제품(n8n)의 노드 추가 방식을 분석해 **빈 캔버스 안내와 + 버튼으로 노드를 추가하는 흐름**을 제안하고 구현했습니다.
- 다시 들어올 때 뜨던 복원 확인 창을 **자동 복구 후 알림**으로 바꾸고, 탭 사이에 섞이던 초안을 워크플로우별로 분리했습니다.
- 편집 화면 하단에 **채팅·실행 로그·노드 값 패널**을 추가해, 실행 결과를 보면서 바로 값을 고칠 수 있는 화면으로 개선했습니다.

## [AI 채팅] 스트리밍 규약 설계와 연결 안정화
2025.10 ~ 2026.08

워크플로우가 10~30초 실행되는 동안 답변·참고 문서·노드 진행 상황을 함께 보여줘야 했고, 이후 중단·테스트 채팅 같은 요구가 계속 더해졌습니다.

- WebSocket 대신 SSE를 택하고, **메시지 종류만 추가하면 기능이 확장되는 규약**을 설계해 백엔드와 합의했습니다. 이후 분기 노드도 기존 코드 수정 없이 추가했습니다.
- 실시간 답변과 저장된 대화 기록의 형식을 통일하고 세 화면에 흩어진 대화 관리를 하나로 모아, **중단한 답변이 사라지던 문제**를 해결했습니다.
- 탭 이동이나 서버 무응답으로 채팅이 끊겨도 사용자가 알 수 없던 문제는, 디버깅과 해결 설계를 나눠 백엔드와 합의한 뒤 **끊김 감지와 자동 재연결**을 구현했습니다. 재연결 대기 시간을 조정해 불필요한 재연결로 인한 서버 부담을 줄이고, 회귀 테스트로 재발을 방지했습니다.

#### 결과

- 실행에 10~30초가 걸려도 TTFT(첫 토큰까지 걸리는 시간) **0.5초 미만**, 운영 서버 반영

## [고객사별 제품 구성] 빌드 없이 서버 설정으로 바꾸는 메뉴 구성
2026.06 ~ 2026.08

고객사마다 계약한 기능이 달라 레포·브랜치를 나눠 대응했고, 한 레포로 합친 뒤에도 메뉴 구성을 바꾸려면 코드를 고치고 다시 빌드해야 했습니다.

- FDE가 빌드 없이 서버에서 메뉴를 켜고 끌 수 있는 **서버 설정 기반 메뉴 구조**를 제안·설계했고, 이 구조가 스펙에 그대로 채택됐습니다.
- 고객사 서버는 늦게 업데이트될 수 있어, **설정이 없는 경우와 빈 목록을 구분**해 구버전 서버에서도 메뉴가 유지되는 구조로 설계했습니다.
- 로그인 후 첫 화면을 대시보드 고정에서 **보이는 첫 메뉴**로 바꿨습니다. 메뉴에서 숨긴 화면은 같은 설정으로 **주소 접근까지 막았고**, 누락 여부는 테스트로 검사했습니다.

#### 결과

- 고객사별 코드 분기 **제거**, 고객사가 늘어도 프론트 코드 수정·재빌드 없음

## [팀 AI 활용] 공용 AI 스킬 구성과 테스트 자동화
2025.09 ~ 현재

AI 코딩 도구를 각자 쓰는 데서 멈추지 않고, 팀이 같은 규칙으로 쓰도록 만들었습니다.

- 레포마다 버전이 갈라지던 스킬 사본을 모아, 두 제품 레포가 함께 쓰는 **팀 공용 Agent Skill 저장소**(PR 리뷰·구조 리뷰·PR 자동화)를 만들었습니다.
- QA 조직 없이 테스트가 늘 뒤로 밀리던 팀에서 테스트 기준을 먼저 정하고, 그 기준에 따라 **Claude Code 서브에이전트가 테스트를 작성·실행하는 흐름**을 동료와 함께 만들었습니다. E2E는 Playwright MCP로 작성·실행하고, 실패하면 GitHub Issue가 자동 등록되는 구조로 구성했습니다.

### [exem-ui](https://ui.ex-em.com/) 디자인 시스템 코어 전환 주도
사내 여러 제품이 쓰는 디자인 시스템에서 화면별로 우회하는 대신 공용 컴포넌트를 만들어 기여했고, 지금은 코어를 **Radix UI에서 Base UI로 전환**하는 작업을 주도하고 있습니다.

### 프론트엔드 선행 API 설계
출시 일정이 급박해 화면에 필요한 정보를 정리하고 **API 인터페이스를 먼저 설계해 백엔드에 전달**했습니다. 덕분에 프론트엔드와 백엔드가 병렬로 개발할 수 있었습니다.
